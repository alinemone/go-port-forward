# ‏pf — مدیریت پورت‌فوروارد

[🇮🇷 فارسی](README.fa.md) • [🇬🇧 English](README.md)

یک ابزار خط فرمان مدرن برای مدیریت چند اتصال `port-forward` به‌صورت هم‌زمان، با نمایش زنده‌ی وضعیت و پشتیبانی از گواهی.

> به‌جای اینکه هر بار چند تا `kubectl port-forward` توی چند ترمینال جدا اجرا کنی، همه رو یک‌بار توی `pf` ذخیره می‌کنی و با یک دستور بالا میاری.

## ✨ امکانات

- 🎨 **محیط ساده (TUI)** — یک صفحه‌ی ترمینالی تمیز با نمایش زنده‌ی وضعیت
- ⚡ **سریع و مطمئن** — قطع شدن اتصال رو سریع تشخیص می‌ده
- 🔄 **اتصال مجدد خودکار** — بعد از قطعی، خودش دوباره وصل می‌کنه
- 🧹 **آزادسازی پورت** — پروسه‌هایی که پورت رو گرفتن خودش می‌بنده
- 🔐 **پشتیبانی از گواهی** — مدیریت داخلی گواهی P12 برای kubectl
- 🌐 **آدرس داخل‌کلاستری روی سیستم خودت** — سرویس رو با همون آدرس پروداکشن لوکال صدا بزن، بدون تغییر تنظیمات
- 📊 **نمایش زنده** — به‌روزرسانی لحظه‌ای وضعیت
- 🛡️ **خروج تمیز** — پاک‌سازی درست موقع خروج یا `Ctrl+C`
- 📦 **یک باینری واحد** — بدون هیچ وابستگی
- 🌍 **چند‌سکویی** — روی ویندوز، لینوکس و مک

## 📥 نصب

آخرین نسخه رو از بخش [Releases](https://github.com/alinemone/go-port-forward/releases) دانلود کن.

### 🪟 ویندوز

فایل `pf-windows-amd64.exe` رو دانلود کن، بعد توی **PowerShell** در همون پوشه این دستور رو اجرا کن. این دستور پوشه‌ی `~/.pf` رو می‌سازه، اسم فایل رو به `pf.exe` عوض می‌کنه، اونجا منتقلش می‌کنه و `~/.pf` رو به PATH کاربر اضافه می‌کنه:

```powershell
$dest = "$HOME\.pf"
New-Item -ItemType Directory -Force -Path $dest | Out-Null
Move-Item -Force .\pf-windows-amd64.exe "$dest\pf.exe"
$userPath = [Environment]::GetEnvironmentVariable("Path", "User")
if ($userPath -notlike "*$dest*") {
    $newPath = if ([string]::IsNullOrEmpty($userPath)) { $dest } else { "$userPath;$dest" }
    [Environment]::SetEnvironmentVariable("Path", $newPath, "User")
}
Write-Host "نصب شد در $dest\pf.exe — یک ترمینال جدید باز کن و بزن: pf"
```

بعد **ترمینال رو ببند و دوباره باز کن** (تغییر PATH فقط روی ترمینال‌های جدید اعمال می‌شه)، حالا از هر جایی می‌تونی بزنی `pf`.

### 🐧 لینوکس / 🍎 مک

فایل مناسب سیستمت رو دانلود کن و با یک دستور نصب کن:

```bash
# لینوکس (Intel/AMD)
mv pf-linux-amd64  pf && chmod +x pf && sudo mv pf /usr/local/bin/

# لینوکس (ARM64)
mv pf-linux-arm64  pf && chmod +x pf && sudo mv pf /usr/local/bin/

# مک (Intel)
mv pf-darwin-amd64 pf && chmod +x pf && sudo mv pf /usr/local/bin/

# مک (Apple Silicon — M1/M2/M3)
mv pf-darwin-arm64 pf && chmod +x pf && sudo mv pf /usr/local/bin/
```

بعد از هر جایی بزن `pf`.

### ساخت از سورس

```bash
go build -trimpath -buildvcs=false \
  -ldflags="-s -w -X github.com/alinemone/go-port-forward/internal/version.Version=dev" \
  -o pf ./cmd/pf
sudo mv pf /usr/local/bin/ && sudo chmod +x /usr/local/bin/pf
```

روی ویندوز به‌جای `-o pf` بزن `-o pf.exe`. برای ساخت نسخه‌ی رسمی با آیکون و همه‌ی سکوها به [نسخه‌ی انگلیسی](README.md#from-source) نگاه کن.

## 🚀 شروع سریع

```bash
# اضافه کردن یک سرویس
pf add db "kubectl port-forward service/postgres 5432:5432"

# اجرای سرویس
pf run db

# اجرای هر دستور kubectl همراه با تزریق خودکار گواهی
pf k get pods -n production

# دیدن همه‌ی سرویس‌ها
pf list
```

> نکته: لازم نیست حتماً `run` بزنی — کافیه اسم سرویس یا گروه رو بنویسی: `pf db`، `pf backend`، `pf db,redis`.

## ⌨️ تکمیل خودکار با Tab

‏`pf` برای **bash، zsh، fish و PowerShell** اسکریپت تکمیل خودکار داره. بعد از فعال‌سازی، با زدن Tab هم دستورها کامل می‌شن و هم **مقادیر پویا** از روی تنظیمات تو — مثل اسم سرویس‌ها، گروه‌ها و تم‌ها.

نصب سریع (پیشنهادی):

```bash
pf completion install            # شل رو خودش تشخیص می‌ده
# یا صریح:
pf completion install bash
pf completion install zsh
pf completion install fish
pf completion install powershell
```

اسکریپت رو زیر `~/.pf/completion/` می‌نویسه و به‌صورت امن (قابل تکرار) به تنظیمات شل وصل می‌کنه. بعد یک ترمینال جدید باز کن. چون اسکریپت فقط باینری `pf` رو صدا می‌زنه، بعد از آپدیت کردن `pf` نیازی به نصب مجدد نیست.

> **cmd.exe** قابلیت تکمیل خودکار نداره؛ روی ویندوز از **PowerShell** یا Git-Bash استفاده کن.

## 🔐 مدیریت گواهی

برای اتصال امن kubectl می‌تونی گواهی P12 اضافه کنی:

```bash
pf cert add "/path/to/certificate.p12"   # افزودن گواهی
pf cert list                             # نمایش گواهی تنظیم‌شده
pf cert remove                           # حذف گواهی
```

**چطوری کار می‌کنه؟**

- گواهی و کلید خصوصی رو از فایل P12 بیرون می‌کشه
- اون‌ها رو به‌صورت امن در `~/.pf/certs/` نگه می‌داره
- فلگ‌های `--client-certificate` و `--client-key` رو خودکار به دستورهای kubectl و `pf k ...` اضافه می‌کنه
- رمز فقط موقع نصب لازمه و **ذخیره نمی‌شه**

## 💡 مثال‌های کاربردی

### مدیریت پایه‌ی سرویس

```bash
# افزودن چند سرویس
pf add db    "kubectl -n prod port-forward service/postgres 5432:5432"
pf add redis "kubectl port-forward service/redis 6379:6379"
pf add api   "kubectl port-forward deployment/api 8080:8080"

pf list                # لیست همه
pf run db              # اجرای یک سرویس
pf run db,redis,api    # اجرای چند سرویس با هم
pf delete redis        # حذف
```

### همراه با گواهی

```bash
pf cert add company-vpn.p12   # ۱) افزودن گواهی (رمز رو وارد کن)
pf add production "kubectl -n prod port-forward service/postgres 5432:5432"   # ۲) گواهی خودکار استفاده می‌شه
pf run production             # ۳) اجرا
```

### تغییر نام سرویس یا گروه

```bash
pf rename db database          # تغییر نام سرویس (عضویت گروه‌ها خودکار به‌روز می‌شه)
pf group rename backend back   # تغییر نام گروه
```

### افزودن / حذف سرویس در گروه

```bash
pf group add-service    database wallet-pg,redis   # افزودن (تکراری‌ها حذف می‌شن)
pf group remove-service database redis             # حذف
```

### ویرایش دسته‌جمعی تنظیمات

```bash
pf edit   # همه‌ی سرویس‌ها و گروه‌ها رو در $EDITOR باز می‌کنه
```

برای راه‌اندازی اولیه که می‌خوای چند سرویس رو یک‌جا اضافه کنی عالیه. موقع ذخیره اعتبارسنجی می‌شه؛ JSON نامعتبر رد می‌شه و بهت پیشنهاد می‌ده دوباره بازش کنی و درستش کنی.

### آیکون‌های اختیاری سرویس

> **به یک [Nerd Font](https://www.nerdfonts.com) نیاز داره.** این آیکون‌ها فقط با فونت Nerd Font نمایش داده می‌شن؛ بدون اون به‌صورت مربع خالی دیده می‌شن — به همین دلیل **پیش‌فرض خاموش‌اند**.

```bash
pf icon on       # روشن کردن آیکون‌های رنگی
pf icon off      # خاموش کردن
pf icon          # نمایش وضعیت
```

آیکون بر اساس پورت اصلی (سمت راست `local:remote`) انتخاب می‌شه. می‌تونی زیر کلید `icon.ports` در `~/.pf/services.json` گلیف و رنگ هر پورت رو دلخواه تغییر بدی.

### 🎨 تم رنگی دلخواه

علاوه بر تم‌های آماده (`default`، `ocean`، `sunset`)، می‌تونی زیر کلید `themes` در `~/.pf/services.json` تم خودت رو تعریف کنی:

```json
{
  "theme": "material",
  "themes": {
    "material": {
      "text": "#E0E0E0", "muted": "#9E9E9E", "border": "#FF5252",
      "accent": "#D32F2F", "warn": "#FFB300", "error": "#B71C1C",
      "heading": "#F5F5F5", "selected": "#8E0000"
    }
  }
}
```

بعد فعالش کن:

```bash
pf theme material   # فعال‌سازی
pf theme            # لیست تم‌ها
```

هر فیلد اختیاریه و روی تم `default` سوار می‌شه، پس تم ناقص هم معتبره. رنگ‌های وضعیت سلامت سرویس (سبز/زرد/قرمز) عمداً در همه‌ی تم‌ها ثابت‌اند تا وضعیت همیشه یکسان خونده بشه.

## 🌐 آدرس داخل‌کلاستری روی سیستم خودت (Alias)

می‌تونی سرویسِ پورت‌فورواردشده رو با **همون آدرسی که در پروداکشن داره** روی سیستم خودت صدا بزنی — بدون تغییر `.env` برنامه.

وقتی روشنش کنی، اجرای یک port-forward از نوع `svc/` (یا `deploy/`، `statefulset/` و…) یک خط به فایل hosts سیستم اضافه می‌کنه:

```
127.0.0.1  operation-dastyar-psql-postgresql-ha.prod-operation.svc.cluster.local
```

آدرس خودکار از روی دستور ساخته می‌شه: `svc/NAME` به‌علاوه‌ی `-n NAMESPACE` می‌شه `NAME.NAMESPACE.svc.cluster.local`.

> **درباره‌ی پورت:** فایل hosts فقط اسم رو به IP وصل می‌کنه و پورت رو نگه نمی‌داره. پس سرویس رو با **پورت لوکالِ** خودت صدا می‌زنی (مثلاً `1116` در `1116:5432`)، نه پورت راه‌دور. یعنی `<fqdn>:<localPort>`.

این قابلیت **پیش‌فرض خاموشه** (چون فایل محافظت‌شده‌ی سیستم رو ویرایش می‌کنه):

```bash
pf alias on        # روشن
pf alias off       # خاموش
pf alias           # وضعیت
pf alias clear     # پاک کردن بلوک باقی‌مانده از فایل hosts
```

**دسترسی مدیر، بدون ترمینال جدید.** ویرایش فایل hosts به دسترسی Administrator (ویندوز) یا root (یونیکس) نیاز داره. موقع `pf run`، خودش با **یک درخواست UAC** (ویندوز) یا **یک sudo** (یونیکس) یک هِلپر پنهان اجرا می‌کنه که آدرس‌ها رو همگام نگه می‌داره و موقع خروج — حتی با `Ctrl+C` — خودکار پاک‌شون می‌کنه. اگه درخواست رو رد کنی، پورت‌فوروارد همچنان روی `localhost:<port>` کار می‌کنه.

در محیط اجرا یک ستون **ALIAS** آدرس هر سرویس رو نشون می‌ده و با زدن **`y`** آدرس سرویس انتخاب‌شده کپی می‌شه.

برای حالت‌های پیشرفته (آدرس دلخواه هر پورت، چند کلاستر با `--context`) به [نسخه‌ی انگلیسی](README.md#-cluster-host-aliases) نگاه کن.

## 🎮 کلیدهای محیط اجرا (TUI)

هنگام اجرای سرویس‌ها:

- **↑↓** یا **j k** — جابه‌جایی بین سرویس‌ها
- **PgUp** / **PgDn** / **چرخ ماوس** — اسکرول پنل لاگ
- **L** — تغییر نمای لاگ (همه‌ی سرویس‌ها / فقط سرویس انتخاب‌شده)
- **Ctrl+L** — پاک‌کردن لاگ‌های نمای فعلی (همه‌ی سرویس‌ها یا فقط سرویس انتخاب‌شده)
- **r** — ری‌استارت سرویس انتخاب‌شده
- **Ctrl+R** — ری‌استارت همه
- **s** — توقف سرویس انتخاب‌شده
- **a** — افزودن یک سرویس ذخیره‌شده‌ی دیگر به لیست در حال اجرا
- **c** — ویرایش دسته‌جمعی تنظیمات در `$EDITOR`
- **y** — کپی آدرس داخل‌کلاستری سرویس (وقتی `pf alias` روشنه)
- **q** یا **Esc** یا **Ctrl+C** — خروج و توقف همه

## 📂 محل فایل‌ها

```
~/.pf/
├── certificate.json      → تنظیمات گواهی
├── services.json         → سرویس‌ها و گروه‌ها
└── certs/
    ├── client-cert.pem   → گواهی استخراج‌شده
    └── client-key.pem    → کلید خصوصی
```

> در اولین اجرا، اگر `services.json` قدیمی کنار فایل اجرایی باشه، خودکار به `~/.pf/services.json` منتقل می‌شه.

## 🔧 چطوری کار می‌کنه؟

1. **مدیریت پورت** — پروسه‌هایی که پورت هدف رو گرفتن تشخیص می‌ده و می‌بنده
2. **ذخیره‌سازی سرویس** — سرویس‌ها در `~/.pf/services.json` ذخیره می‌شن
3. **اتصال مجدد خودکار** — با backoff نمایی وقتی پروسه خارج می‌شه یا kubectl خطای مرگبار می‌ده دوباره وصل می‌کنه؛ هیچ‌وقت برای همیشه ول نمی‌کنه
4. **تزریق گواهی** — برای دستورهای kubectl فلگ‌های گواهی رو خودکار اضافه می‌کنه
5. **پاک‌سازی پروسه‌ها** — موقع خروج همه‌ی پروسه‌ها درست بسته می‌شن

## 🛡️ امنیت

- رمز فایل P12 فقط موقع استخراج استفاده می‌شه و **هیچ‌وقت ذخیره نمی‌شه**
- فایل گواهی و کلید با دسترسی `0600` (فقط مالک) ذخیره می‌شن
- همه در پوشه‌ی خانگی کاربر (`~/.pf/`) نگه‌داری می‌شن

> **نکته‌ی آنتی‌ویروس:** این ابزار دستورهای سیستمی (kubectl، ssh) اجرا می‌کنه و اتصال شبکه مدیریت می‌کنه، برای همین ممکنه آنتی‌ویروس اشتباهی حساس بشه. در صورت نیاز از سورس بسازش یا برای مسیرش استثنا اضافه کن.

## 🐛 رفع اشکال

- **پورت اشغاله؟** بزن `pf cleanup`.
- **گواهی کار نمی‌کنه؟** مسیر و رمز فایل P12 رو چک کن، بعد `pf cert list`.
- **سرویس بالا نمیاد؟** دستور kubectl رو دستی تست کن و context و دسترسی‌ها رو بررسی کن.
